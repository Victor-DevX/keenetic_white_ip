# Keenetic PPPoE Auto Reconnect

Скрипт для роутеров Keenetic (NDMS), который автоматически переподключает PPPoE-сессию при получении серого (CGNAT) IP-адреса, чтобы получить "белый" публичный IP.

Полезно для:
- прямого удалённого доступа через KeenDNS (в прямом режиме)
- использования роутера как VPN-сервера
- стороннние DDNS
- self-hosted сервисов на роутере :)


---

## Возможности
- **Интерфейс:** PPP_INTERFACE="PPPoE0".
- **Проверка IP на принадлежность к "серым" диапазонам:**
  - `10.0.0.0/8`
  - `100.64.0.0/10`
  - `172.16.0.0/12`
- **Умная защита от бана провайдером:** Использует рандомизированную паузу (5-15 сек) между попытками. После 5 неудачных попыток уходит в спящий режим на 5 минут, чтобы биллинг ISP не заблокировал порт за спам авторизациями.
- **Логи на USB-накопителе:** Все служебные файлы (логи, счётчик попыток и последний полученный IP) хранятся в Entware в каталоге:/opt/var/log/wh_ip.
- **Надежная блокировка:** Исключает конфликт параллельных процессов при частых обрывах связи.

---

## Требования
- Роутер Keenetic с USB-портом.
- Установленная среда **Entware** (на USB-накопителе).
- PPPoE-подключение должно подниматься непосредственно на самом Keenetic (если перед ним стоит оптический терминал провайдера, он должен быть переведен в режим Bridge).

### Необходимые компоненты
Перед установкой убедитесь, что в Entware установлены нужные утилиты:
- `wget` или `curl` (для скачивания)

Проверить и установить можно командами:
```sh
opkg update
```
```sh
opkg install wget curl
```

Проверить наличие можно командами:
```sh
which wget
```
```sh
which curl
```

Если `wget` отсутствует:
```sh
opkg install wget
```

Если `curl` отсутствует:
```sh
opkg install curl
```

## Ручная проверка (Отладка)
Так как скрипт ожидает переменные от системы NDMS, простой запуск файла может ничего не дать (скрипт безопасно завершится если у Вас уже белый IP). Для эмуляции получения серого IP выполните в терминале команду:
```sh
address="100.64.1.10" interface="ppp0" sh /opt/etc/ndm/wan.d/pppoe_reconnect
```

---
## Настройка
Основные параметры:

```sh
"$interface" != "ppp0"   # Имя PPPoE-интерфейса в NDMS
max_tries=5              # Количество быстрых попыток реконнекта
long_pause=300           # Пауза после исчерпания лимита (секунды)
max_log_size=10240       # Лимит размера лог-файла (10 КБ)
```

При необходимости можно изменить интерфейс и количество попыток реконнекта.

## Логиирование
Все служебные файлы хранятся в каталоге:
```sh
/opt/var/log/wh_ip/
```
Файлы:
 ||reconnect.log — история подключений и переподключений.
 ||counter.txt — счётчик неудачных попыток.
 ||previp.txt — последний успешно полученный белый IP.

```sh
/opt/var/log/pppoe_guard.log"
```

Для отключения логирования замените строку:
```sh
log="$workdir/reconnect.log"
```
на 
```sh
log="/dev/null"
```

## Удаление
```sh
rm /opt/etc/ndm/wan.d/pppoe_reconnect
rm -rf /opt/var/log/wh_ip/
```

## Как работает

1. Скрипт запускается системой NDMS при получении IP-адреса на WAN-интерфейсе.
2. Обрабатываются только события PPPoE-интерфейса (ppp0), полученные от системы NDMS.
3. Проверяет, является ли IP серым.
4. Если IP-адрес "серый":
   - увеличивается счётчик попыток;
   - выполняется реконнект PPPoE через случайную задержку 5-15 секунд;
   - после 5 неудачных попыток выполняется пауза 5 минут.
5. Если IP-адрес "белый":
   - счётчик сбрасывается;
   - сохраняется новый IP для последующих сравнений.

---
## Примечание

Скрипт вызывается системой NDMS через каталог хуков wan.d при изменении состояния WAN-подключения, поэтому не требует настройки планировщика (cron).
